# Ground routes — 2026-10-28

Routes now use decoded walkable terrain, ground heights and the current camera to draw on the floor. A compact, independently draggable legend identifies each destination by its line color. Position and settings persist; modules still start disabled. The overlay never moves the character.

## Controls and behavior

- Destination switches: area exits, boss-area terrain landmarks and living bosses/uniques, waypoints, quest objects and unused encounter objects. Terrain landmarks are read for the entire loaded zone, independently of nearby entities, so recognized destinations are routed on entry. Exact current/observed entity positions replace approximate terrain approaches without duplicate routes.
- One entry per named destination; multiple observed entrances are evaluated for the shortest reachable approach. Colors remain stable in the instance.
- Drawing rate: 60/90/120/144 fps. Path refresh: 1/2/5/10 per second. These are targets; Windows scheduling and game/data availability affect achieved timing.
- Stability: Always shortest, Balanced (default), Prefer existing route. Balanced requires at least 8 grid cells and 12% saving before changing a usable route; Prefer existing requires 12 cells and 25%. Broken connections are replanned regardless of savings.
- The nearby path is trimmed and safely connected to the player's latest position each frame, without waiting for a full search. Within the existing corridor, Balanced compares alternatives at most every 2 seconds (Prefer existing: 4 seconds). This deliberately trades small time savings for visual consistency.
- Line width/opacity and legend font, width, opacity, anchor and click-through lock are configurable. Dragging the unlocked legend consumes the click.

## Fixes and measurements

The earlier long A* searches shared Python execution time with the memory reader. Recorded reads occasionally approached 965 ms, exceeding the 300 ms freshness boundary and hiding the entire overlay. Live searches now run in a separate persistent process, with terrain transferred once per instance and cancellation on zone changes. Freshness and foreground checks remain in place.

The accepted process-isolation capture (`.reference/routes-process-test.json`, The Wetlands) recorded a median 8.03 ms paint interval, 10.19 ms p95, median 1.34 ms paint work, and 3.08 ms p95 paint work. Reader median was 15.88 ms, p95 29.90 ms, max 117.29 ms. Whole-capture maxima include startup/focus pauses and do not establish uninterrupted frame delivery. The user confirmed the legend stayed visible and longer searches completed.

Subsequent stability changes update the lead-in locally, compare old and new remaining costs from the current player position, and retain a valid route if a background candidate fails. No direct shortcut through blocked cells is drawn. The old instance cache is rejected after game/process restart.

## Arena transition sides

Cells exposed both sides of an internal transition in the same terrain instance: the active Arena entrance was in walkable region 1 and the reverse-side terrain exit in region 12. Both were selected for the legend even though only the current side had a walkable path.

The reader now labels nonzero walkable regions once per terrain generation, on its background reader thread. Four-connected components exactly describe reachability for the planner's corner-safe eight-way movement. The immutable labels are shared with snapshots. Routes filter destination approaches against the player's current region before sorting, applying the route limit or building lines/legend rows. Blocked transition cells use the same bounded nearest-walkable snapping as search. Separate approaches to one named destination are filtered individually. Discovery is retained so the reverse route becomes available on entering the arena; the opposite side is not deleted permanently.

All 103 tests pass, including Arena → Cells → Arena switches without changing the instance, one corresponding line/legend entry per side, retained discovered exits, separate regions across diagonal corners, narrow corridors and cache invalidation on new terrain. A read-only live snapshot plus an offline opposite-side position replay is recorded in `.reference/route-transition-region-validation-20261028.json`; replay does not move the game or constitute a live traversal test.
